# Shoresh PGH

Responsive React, TypeScript, Vite, Tailwind CSS, and Framer Motion site with shared green-and-white branding.

## Brand Files

- `src/assets/shoresh-logo.svg`: a local vector reconstruction of the supplied screenshot's cup, steam, hand-lettered wordmark, and tagline. No photo background, remote image references, or external fonts are needed to display it. Replace this file with the original vector artwork if exact original outlines become available.
- `src/components/BrandLogo.tsx`: the same artwork in green-on-white, white-on-green, and mark-only treatments.
- `src/theme.css`: primary colors `#1C584F` and `#FFFFFF`, their derived tints, and font families.
- `src/brand.ts`: logo source and named photography slots.
- `src/components/Loader.tsx`: responsive welcome animation, reduced-motion support, a skip button, a maximum wait, and once-per-session behavior. The footer's Replay welcome button lets you view it again.

The logo is imported into the production bundle. It does not depend on localStorage, a database response, Wix, or a root-relative image request. This makes the branding work on a Vercel domain and a GitHub Pages repository subpath.

## Development

Use Node.js 22. Install dependencies with `npm install`, then start the site with `npm run dev`. The production output is generated by the existing `npm run build` script and is written to `dist/`.

## Vercel

Connect this GitHub repository to Vercel. The included `vercel.json` uses the Vite preset and the `dist` output folder. No environment variables are required for the logo or branding. Pages use hash navigation, so a server-side route rewrite is not needed.

## GitHub Pages

In repository Settings > Pages, choose GitHub Actions as the source. The included `.github/workflows/pages.yml` builds and deploys on pushes to `main`, or through Run workflow. Change the branch in that file if your default branch is different. JavaScript, styles, and SVG branding are embedded by the existing single-file Vite configuration.

## Save The Logo In Supabase

No database connection or credentials were available during this update. Files have not been uploaded to a live database. The following optional setup stores the green, white, and mark-only assets in Supabase Storage and their URLs and checksums in a database table:

1. Apply `supabase/migrations/202606010001_brand_assets.sql` in your project's SQL editor or migration workflow.
2. Copy `.env.example` to a private `.env.local` file and set `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`.
3. Run `node --env-file=.env.local scripts/upload-brand-assets.mjs` in a trusted local or server environment.
4. Confirm the three objects in the public `shoresh-branding` bucket and their records in `public.brand_assets`.

The script validates responses and reports any upload or metadata failure. It is safe to rerun: files and records are upserted. Do not put the service-role key in a `VITE_` variable, frontend code, or GitHub. Public clients have read-only access to brand metadata and no upload policy. The website intentionally retains its bundled source, so a storage outage cannot hide the logo or block the loader.

## Preview Limitations

This repository contains one site implementation; its light and dark brand treatments share the same logo and tokens. No second design repository was provided.

Existing class, product, RSVP, contact, and donation flows use browser-local demonstration data, not a connected production backend. Live email, authenticated administration, Stripe payments, verified class schedules, menu pricing, fundraising totals, and legal details must be connected or confirmed before accepting real registrations, orders, or gifts. The preview checkout does not collect card details or charge a card.

Deployment configuration and the optional Supabase upload need verification in your own hosting and Supabase accounts. Original founder portraits are still needed; stock models are not presented as the founders.
